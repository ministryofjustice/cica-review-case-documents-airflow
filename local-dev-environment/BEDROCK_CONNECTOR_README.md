# Bedrock Connector Guide

This guide documents the [Bedrock connector](https://docs.opensearch.org/latest/ml-commons-plugin/remote-models/connectors/) and related OpenSearch pipelines for this repository.
- [Flow Diagram](/local-dev-environment/diagrams/bedrock-connector-flow.mermaid)
- See the [Runbooks](/runbooks/RUNBOOK.md) for initial setup and working with local and remote environments.

## Current behavior

- The default search pipeline configures `neural_query_enricher` only.
- Hybrid-score normalization and branch score-combination processors are intentionally not configured at this time.
- Reintroduction of score fusion should be based on dedicated evaluation and agreed tuning values.

## Scripts and ownership

Primary setup entrypoints:

- LocalStack init flow: `init-scripts/03-setup-bedrock-connector-neural.sh`
- Port-forward flow: `setup-bedrock-connector-portforward.sh`

Shared implementation:

- `init-scripts/lib/bedrock_connector_common.inc`

When changing connector/model/pipeline behavior, update the shared library first and keep entrypoint scripts focused on environment-specific bootstrapping and auth.

## Connector recreation

You will need to recreate the connector for
- AWS key rotation (local development only)
- after recreating the indexes
- making changes to the connector

### Local dev environment
From the repo root directory
```bash
cd local-dev-environment/

docker compose exec -e BEDROCK_FORCE_RECREATE_CONNECTOR=true localstack \
  bash /etc/localstack/init/ready.d/03-setup-bedrock-connector-neural.sh
```

### Remote port forwarded environment DEV/UAT
From the repo root directory
```bash
cd local-dev-environment/

BEDROCK_FORCE_RECREATE_CONNECTOR=true CONFIRM_OVERWRITE=true ./setup-bedrock-connector-portforward.sh
```

And follow the usage instructions within the [script](/local-dev-environment/setup-bedrock-connector-portforward.sh).


## Optional flags:

- `BEDROCK_FORCE_RECREATE_CONNECTOR=true` to force connector/model recreation
- `CONFIRM_OVERWRITE=true` to skip interactive overwrite prompts

Example:

```bash
BEDROCK_FORCE_RECREATE_CONNECTOR=true CONFIRM_OVERWRITE=true ./setup-bedrock-connector-portforward.sh
```

## Confirm overwrite behavior

`CONFIRM_OVERWRITE` controls behavior when existing pipelines or index settings are found:

- `prompt` (default): ask before overwriting
- `true`: overwrite without prompting
- `false`: fail instead of overwriting

## Ingest embedding toggle

`BEDROCK_ENABLE_INGEST_PIPELINE` controls ingest-time embedding generation:

- `false` (recommended local default): `default_pipeline` is set to `_none`
- `true`: ingest pipeline `bedrock-embedding-pipeline` is configured and used

When set to `false`:

- Document embeddings are generated by the ingestion app before indexing.
- Query embeddings are generated at search time via the default search pipeline.

## Verification checks

Check search pipeline definition:

```bash
curl -s http://127.0.0.1:9200/_search/pipeline/bedrock-neural-search-pipeline | jq
```

Expected: request processors include `neural_query_enricher`.

Check index default pipelines:

```bash
curl -s http://127.0.0.1:9200/page_chunks/_settings | jq '.page_chunks.settings.index | {default_pipeline, search_default_pipeline: (."search.default_pipeline" // .search.default_pipeline)}'
```

Check model state:

```bash
curl -s http://127.0.0.1:9200/_plugins/_ml/models/<MODEL_ID> | jq '.model_state'
```

`PARTIALLY_DEPLOYED` may be acceptable on smaller dev clusters if queries succeed.

## Troubleshooting

For symptom-to-fix troubleshooting steps (including expired AWS token handling), see [/docs/TROUBLESHOOTING.md](/docs/TROUBLESHOOTING.md).

## Security notes

- Run port-forward setup only from a local machine you control.
- Avoid storing `OPENSEARCH_PASSWORD` or `OPENSEARCH_BEARER_TOKEN` in shell startup files.
- Prefer short-lived terminal environment variables and clear them after use.
- Stop port-forward sessions after setup is complete.
